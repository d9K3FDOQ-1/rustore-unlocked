# RuStore Unlocked — LSPosed-модуль

Применяет функции мода к **оригинальному** RuStore через хуки LSPosed, не
трогая и не переподписывая APK. RuStore остаётся настоящим и подписанным
ключом RuStore, поэтому **вход через VK ID работает** как обычно — в отличие
от переподписанного APK из корня репозитория.

Привязано к RuStore **1.112.0.4**. Имена целевых классов обфусцированы R8 и
меняются от версии к версии.

## Что делает

Хуки в процессе `ru.vk.store` (`UnlockedXposed.handleLoadPackage`):

| Функция | Класс/метод (1.112.0.4) | Что возвращает |
|---|---|---|
| Убрать рекламу | `z81.e0.a(...)` | пустой список рекламных слотов |
| Скрыть VPN | `TunDetectorRemoteConfig.isTunDetectEnabled` | `false` |
| Скрыть VPN | `gz2.c.a()` | `false` |
| Показывать Коннект | `ConnectAvailabilityRemoteConfig.isEnabled` | `true` |
| Показывать Коннект | `mc1.i.d()` | `ConnectAvailabilityStatus.REVERSE` |

Каждый хук проверяет настройку перед подменой результата. Если функция
выключена (или настройки не прочитались) — метод работает штатно; по умолчанию
все функции включены.

**Подтверждение загрузки.** При старте RuStore модуль один раз показывает тост
«RuStore Unlocked ✅ загружен» (или «⏸ выключен», если снят главный
выключатель) — сразу видно, что хуки прицепились.

**Настройки.** Иконка модуля открывает экран с переключателями (главный
выключатель + три функции). Настройки пишутся в мир-читаемый файл
(`MODE_WORLD_READABLE`), который хук читает через `XSharedPreferences`. После
смены переключателей RuStore нужно перезапустить. Если LSPosed не смог сделать
файл доступным процессу RuStore, экран покажет предупреждение, а функции
останутся включёнными по умолчанию.

Реклама в post-view (`l91.s`) и админ-слоты (`z81.n`) не хукаются: их методы
возвращают обфусцированный `kotlin.Result`, который сложно собрать из хука.
Основной путь показа рекламы (`z81.e0`) перекрыт, видимой рекламы быть не должно.

## Установка

1. Нужен root (Magisk/KernelSU) и установленный **LSPosed**.
2. Поставьте **оригинальный** RuStore (не переподписанный). Если он уже стоит из
   RuStore/магазина — ничего переустанавливать не надо.
3. Установите `rustore-unlocked-xposed.apk`.
4. В LSPosed → Модули включите «RuStore Unlocked (Xposed)», в области действия
   отметьте **RuStore**.
5. Принудительно остановите и откройте RuStore заново.

Иконка модуля открывает экран со статусом и справкой; сам он ничего не
включает — всё делает хук внутри RuStore.

## Сборка

```bash
scripts/build-xposed.sh        # → work/xposed-out/rustore-unlocked-xposed.apk
```

Код модуля компилируется против заглушек Xposed API (`xposed/stubs`), но в dex
попадают только классы модуля — настоящие `de.robv.android.xposed.*` даёт
LSPosed в рантайме. APK собирает apktool (встроенный aapt2) и подписывает
uber-apk-signer (debug-ключ, либо свой через `KEYSTORE/KEY_ALIAS/...`).

### Перенос на новую версию RuStore

Обфусцированные имена (`z81.e0`, `mc1.i`, `gz2.c`) после обновления RuStore
поменяются. Найти заново — так же, как для smali-патчей (см. корневой README):
декомпилировать новый APK и сопоставить по строкам ресурсов и сигнатурам
методов, затем обновить константы в `UnlockedXposed.java`. Имена с настоящими
пакетами (`TunDetectorRemoteConfig`, `ConnectAvailabilityRemoteConfig`,
`ConnectAvailabilityStatus`) обычно стабильны.
